# Security policy

Employ-Minds is an instruction/workflow harness, so its highest-impact security surfaces are installer behavior, trust-boundary guidance, destructive operations, and any future automation that can execute commands or mutate repositories.

## Reporting

Please report suspected vulnerabilities privately through GitHub's repository security reporting features when available. Do not publish exploit details in a public issue before maintainers have had a reasonable opportunity to investigate.

Useful reports include: affected version/commit, reproduction steps, expected versus actual behavior, impact, and a minimal proof of concept that does not expose third-party secrets or data.

## Scope principles

Security fixes must not silently weaken project requirements. CRITICAL work remains blocked while material security or data-safety findings are unresolved.
