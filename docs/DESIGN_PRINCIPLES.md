# Design principles

1. **Quality per token.** Spending fewer tokens is useful only if correctness and safety do not fall.
2. **Progressive disclosure.** Map -> targeted evidence -> full material. Context is earned by a concrete question.
3. **Strong cognition is scarce.** Retrieval/classification can use cheaper minds; architecture, hard debugging and consequential review deserve stronger reasoning.
4. **Reasoning and editing are separable.** Pay for an Architect only when a design decision exists; keep mechanical execution bounded.
5. **Writer != judge.** STANDARD/CRITICAL work gets independent spec/quality verification contexts. CRITICAL adds security.
6. **Evidence beats confidence.** Completion claims map to fresh checks after the final relevant change.
7. **Risk pays for ceremony.** FAST work stays fast. Critical work earns rollback, isolation, independent review, and stronger verification.
8. **One question, one owner.** Duplicate agents are waste unless deliberate independent diversity can improve a consequential decision.
9. **Stop useless loops.** Repeated action without new evidence triggers a hypothesis change or re-plan.
10. **Anti-bloat.** A skill, mind, gate, or prompt survives only if removing it measurably harms safety, correctness, uncertainty reduction, or context economy.
11. **Benchmarks over aesthetics.** Harness tests prove mechanics; coding evals prove performance. Never confuse them.
12. **Human-shaped output.** Prefer concise, contextual reasoning and repository-native conventions over templated agent theater. Do not add ceremony to make work look sophisticated.
