# Employ-Minds Research

Use when implementation depends on versioned APIs, recent framework behavior, obscure protocols, security guidance, or external facts likely to change.

1. State the exact implementation question.
2. Prefer official documentation, specifications, source repositories, release notes, and primary research.
3. Record relevant version/date constraints.
4. Distinguish documented behavior from inference.
5. Translate findings into concrete implementation/test constraints.
6. Test version-sensitive behavior locally when practical.

Do not copy examples blindly. Adapt them to the repository architecture and threat model. Preserve uncertainty explicitly when authoritative sources disagree.
